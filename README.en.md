# Enterprise Engineering & Operations Intelligence

**An intelligence layer on top of the tools a company already runs, answering what they do not:
why did this happen, what changed, who is affected, and what did it cost.**

This repository holds two things: the **full product specification** (13 PRDs, 21 ADRs, 17
SPECs, architecture, roadmap, UX and governance — in Portuguese) and a **working demo** that
implements the first slice of it and actually runs on a Databricks workspace.

---

## The demo in one screen

A sales job that used to run in minutes started taking **26**. The Spark UI shows the number.
The platform shows the cause:

![Incident with hypotheses and evidence](demo/img/02-rca-evidencias.png)

**Top hypothesis, 0.9 confidence, four pieces of evidence:**

| Evidence | What it says |
|----------|--------------|
| Key distribution | One customer holds **40** % of rows — **24** million out of **60** million |
| Execution plan | A new `Window` operator, absent from the healthy run |
| Change | The commit that introduced the window, with the file it touched |
| Volume | Input did **not** grow — rules out the most common explanation |

Alternative hypotheses stay visible at **0.05**, each with the evidence that knocks it down.
No inference goes above **0.9** without human confirmation.

And the summary text? It was written by rule: the language model's output **was rejected** in
validation because it did not cite evidence in the required format.

## What this proves

| Claim | How it is verified |
|-------|--------------------|
| Detects real regression | Healthy baseline against a **1570** s run — factor **5.7** |
| No alert flood | **2** slow runs → **1** incident, recurrence on the timeline |
| Diagnoses with evidence | **4** items, including one that **rules out** a competing hypothesis |
| Links technical to business | **3** affected assets via catalog lineage, including a dashboard |
| Measures cost | **0.0682** dollars of incremental cost, from the billing table |
| Never invents | Missing sources read as unavailable; ungrounded LLM output is discarded |
| Is software, not slideware | **100** tests, **96** % coverage on the domain core |

Every number above comes from `demo/numbers.json`, generated by querying the tables. A checker
(`demo/verify_demo.py`) fails any document that cites a number without a declared source.

## Running it

Prerequisites: a Databricks workspace (validated on a **serverless-only** environment), the
Databricks CLI authenticated, and Python 3.11+.

```bash
git clone https://github.com/JonatasLimaBR/enterprise-intelligence.git
cd enterprise-intelligence/eict-platform

python -m venv .venv && .venv/bin/python -m pip install -e ".[dev]"   # Windows: .venv/Scripts/python
.venv/bin/python -m pytest -q

databricks warehouses list --profile <profile>
databricks bundle deploy -t dev --profile <profile> --var="warehouse_id=<id>"
```

Full walkthrough — including the staged workload and the live trigger — in
[`demo/README.md`](demo/README.md). The complete scenario burns a few hours of serverless
compute; the demo kit freezes the real state and restores it in seconds.

## How it works

```text
monitored job ──► Jobs API + run profile + GitHub
                        │
            bronze ──► silver ──► gold (per-run features)
                        │
            correlator (pure Python, no Spark)
              baseline → detection → comparison → rule-based hypotheses
              → idempotent incident → lineage → cost
                        │
            narrator (LLM) → evidence validation → console
```

**The organising principle:** ranking is deterministic and auditable; the language model only
drafts, and only citing evidence that exists. Trade-offs in
[`demo/ARQUITETURA.md`](demo/ARQUITETURA.md) (Portuguese).

## What the demo does not do yet

Stated plainly, because a declared limit is worth more than a promise: no automated
remediation, no recurring-problem management, no data quality or contracts. The ITSM ticket is
implemented but not configured. A question-by-question map is in
[`demo/PERGUNTAS.md`](demo/PERGUNTAS.md).

**A note on process:** **8** of the most relevant problems only appeared when running for real
— Spark type inference, an ambiguous column, timezone handling, the model's response format.
No local test would have found them, and each became a test afterwards.
